# 新电脑验收

当前仓库的回归测试不能代替以下目标机验收。每一项分别记录 PASS / FAIL / 未测试，保留脱敏时间与版本，不保存订阅或账号内容。

1. 核对主 Clash 实际 Rule、TUN、端口及有序规则；东京只指向本机网关，Claude 本体／Helper 的 TCP 规则先于通用 Stripe／Intercom，相关 UDP 拒绝。
2. 从东京入口访问两个公共出口检查服务，确认同一个预期 IPv4 且地区 JP。公共查询只携带普通网络请求，不提交登录凭据。
3. 在隔离副本测试主日本中转失败、备用失败、住宅失效、出口不符、人工锁定、检查超时；核对新连接被拒绝、旧连接关闭、没有 DIRECT 或裸机场回退。
4. 在保存任务后验收暂停／恢复 TUN、退出／重启 Clash、正常重启 Mac；暂时故障恢复仍需新鲜核验，人工锁和规则／IP 异常不得自行清除。异常强杀与正常重启分开验收。
5. 打开真实 Claude Desktop，观察本体与 Helper 的 API、资源、遥测／第三方域名实际命中东京。不能只按目标服务器“地区”判断出口。
6. 验收独立 Chrome 的实际网页出口、防护扩展、需要的 WebRTC／UDP 故障行为。未通过时不要完成登录。
7. 登录模式逐条验证当前客户端确实走系统浏览器；若出现原生认证窗口，标记未验收并停止该路径。完成后验证原浏览器恢复。
8. 验收配置内 SSH、Git、AWS 包装器；Codex 子进程的代理环境和实际 socket／Clash 路由应为美国住宅，父 Claude 环境继续东京。远端命令的出站另计。
9. 先在独立目标环境做安装、升级、失败回滚及卸载，确认其他软件和原配置不被修改，再用于长期运行。

默认测试只使用临时回环端口、虚构出口和 mock；不会替使用者执行破坏性生产故障注入。
