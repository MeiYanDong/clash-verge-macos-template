# 权限与保护范围

| 操作 | 权限与影响 |
|---|---|
| init / render / 离线测试 | 当前用户写新目录，不接入生产控制器 |
| prepare | 当前用户生成私有包、编译；明确加 `--bind-live` 才只读核对主 Clash |
| install-system / 升级 / uninstall-system | 本机管理员；只管理 `ClashTokyoTemplate` 的身份、目录、服务和 sudoers |
| install-user / upgrade-user | 当前用户；只管理模板自身的 App、文件和 LaunchAgent |
| install-tools | 当前用户；需退出 Claude；备份并合并自己的 settings，不操作密钥与登录态 |
| status / arm / lock | 固定本机 helper，以服务用户运行；arm 是请求核验，不能直接把灯变绿 |
| 浏览器登录 | 本人完成；不迁移 Cookie、Keychain、密码或旧会话 |

过去开发时对重载、断网测试、临时路径的逐次确认不属于产品依赖。安装后后台程序独立运行，不需要 Codex 常驻。

模板不能保证：

- Clash 停止、TUN 关闭或流量无法归属时，整个 macOS 都绝无直连。东京代理本身会关门，但系统其他路径不由它封锁。
- 任意子进程、远端 VM、远端 SSH 命令、所有浏览器 UDP/IPv6 都被同一入口接管。配置的工具包装器与当前桌面进程规则有明确范围。
- 独立 Chrome 资料目录改变硬件指纹或等同另一台 Mac；也不保证任何平台账号不会被限制。
- 登录接管覆盖 ASWebAuthenticationSession 或未来客户端的所有登录机制。这条系统原生认证路径仍待单独验证；普通系统浏览器跳转的验证不能替代它。
- 双机场能解决同一个住宅出口失效。东京预期 IP 不符保持锁定，需要核对供应商，不能自动接受新 IP。

状态灯是有时效的观测结果。界面隐藏／缓存状态不等于网络健康；隔离解析、模拟测试、配置加载和真实请求成功是不同的证据。

东京 Chrome 中运行的其他扩展请求也可能使用该浏览器的东京代理。它与独立 Codex 客户端、Claude 调用的 Codex 子进程是不同的网络入口，不能互相代替出口验收。

服务代码及授权由 root 持有，业务进程为隐藏服务身份。有限免密权限不等于任意 root 权限，也不是 Codex 独占权限。同一用户下的其他程序同样可能调用已授权的三个命令。

`install-system` 不自动启用 TUN、不改变默认浏览器。首次安装可能需要 Clash 自己的系统服务授权；扩展安装和浏览器切换由使用者明确操作。
